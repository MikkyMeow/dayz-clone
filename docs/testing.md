# Проверка изменений

## Автоматическая проверка

Запуск всего набора:

```bash
npm test
```

Тесты используют встроенный `node:test`. Клиентские unit-тесты подставляют минимальные DOM/Canvas stubs, поэтому новая DOM-зависимость в импортируемом модуле может потребовать расширить test harness. Модули, импортируемые сервером (`world.js`, `utils.js`, transitively `spatial-grid.js` и config), должны оставаться пригодными для Node.

## Минимальная матрица ручной проверки

Для механики, общей обоим режимам, пройти обе колонки.

| Сценарий | Single | PvP, минимум 2 клиента |
|---|---:|---:|
| Desktop keyboard/mouse | ✓ | ✓ |
| Touch/coarse pointer | ✓ | ✓ |
| Подключение/перезапуск/потеря сервера | — | ✓ |
| Взаимодействие рядом с закрытой/открытой дверью | ✓ | ✓ |
| Граница мира и столкновение со стеной | ✓ | ✓ |
| Инвентарь: pickup/equip/use/drop/quick slot | ✓ | ✓ |
| Бой: miss/hit/cooldown/стамина/преграда | ✓ | ✓ |
| Смерть и повторный старт/respawn | ✓ | ✓ |
| Долгая вкладка background → foreground | ✓ | ✓ |

Для PvP отдельно проверить конкурентные действия: два игрока подбирают один предмет; оба атакуют; дверь закрывается при занятом проёме; игрок выходит; сущность входит и выходит из AOI.

## Производительность

Открыть игру с `?perf` и сравнить до/после:

- p50/p95/p99 frame time;
- update/render time;
- candidates/rendered/culled;
- количество чанков и частиц;
- размер snapshot.

Проверять как минимум десктоп и мобильный/coarse-pointer viewport. Для роста числа сущностей учитывать `maxAlive`, AOI, culling, `maxSearchesPerFrame`, chunk cache и размер 4096 байт на входящие сообщения (snapshot этим лимитом не ограничен, но влияет на сеть/JSON GC).

## Что покрыто слабо

- Нет browser/e2e тестов и визуальных regression-тестов.
- Нет integration-теста реального WebSocket lifecycle и HTTP allowlist.
- Нет parity-тестов single против server simulation.
- Не покрыты UI/рюкзак, touch input, reconnect, rate limit и shutdown.
- Server zombie AI почти не тестируется.

Изменение в этих областях требует усиленной ручной проверки либо добавления теста на новый контракт.

## Критерии готовности функции

- Продуктовые вопросы из `feature-checklist.md` решены и зафиксированы.
- Владельцы состояния и авторитет однозначны.
- Single/PvP parity либо обеспечен, либо различие намеренно описано.
- Недоверенные payload проверяются сервером.
- UI работает на desktop и touch и не блокирует продолжающуюся игру неожиданно.
- Коллизии, двери, LOS и навигация согласованы.
- Добавлены тесты на happy path, границы и отказ.
- `npm test` проходит; нет ухудшения perf HUD в релевантном масштабе.
- Обновлены docs и пользовательский README, если изменились запуск или управление.
